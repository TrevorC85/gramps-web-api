# Full-tree build for the local Collins Family Gramps Web

This directory rebuilds the tree in Gramps Web from the Genealogy and Genealogy
Wife bot data, then applies `website_manifest.jsonl` attachments. It is
idempotent. Nothing here is public or deployed to AWS; the same scripts are
meant to be pointed at AWS later via `GRAMPSWEB_URL`.

## Environment

- `GRAMPSWEB_URL` (also accepts `GRAMPS_WEB_URL` or `GRAMPSWEB_BASE_URL`) —
  default `http://127.0.0.1:5055`
- `GRAMPSWEB_USERNAME` / `GRAMPSWEB_PASSWORD` — default: the local
  `/workspace/gramps-web/.admin_password` file

## Shared files other bots should use

- Spec: `/workspace/gramps-web/shared/MANIFEST_SPEC.md`
- Person lookup (written by every build, mode 644): `/workspace/gramps-web/shared/people_index.csv`
  columns: `gramps_id, side, name, birth, death, parents, spouses, living`
  Living people are listed by **first name only** (`living=true`).
- Unmatched manifest rows: `/workspace/gramps-web/shared/manifest_unmatched.csv`

### How the research bots should append attachments

1. Look up the person in `people_index.csv` and copy their `gramps_id` (e.g. `I0768`).
2. **Append** one JSON object per line to the side’s manifest (do not rewrite the
   `# --- eng-seed begin/end ---` block; that is regenerated by the build):
   - Trevor’s side: `/workspace/genealogy/website_manifest.jsonl`
   - Cindy’s side: `/workspace/genealogy-cindy/website_manifest.jsonl`
3. Use a unique `id` such as `gen-2026-11-18-001` or `wife-2026-11-18-001`.
4. To correct an entry, append a new line with the same `id` and `"replaces": true`.
   To drop one, append `{"id": "...", "delete": true}`.
5. `kind` is `file`, `url`, `note`, or `spouse`. For files, `path` is an absolute
   path on the box. Only content-confirmed matches; never a generated tree chart.
6. Optional: `source_log` (path to the dated research log — stored as a citation note),
   `negative` (on `kind=note`, a searched-not-found research note, kept private),
   `relation` (`biological|adoptive|step|foster|legal`, default biological) when
   the entry supports a parent link, `also_for` for household/shared records.
7. Then rerun the build (or just `attach_manifest.py` if the tree is already current).

## Large scans, media audit and record links (18 Nov 2026)

- **Files over 10 MiB** are never uploaded as-is. `media_prep.py` (used by `attach_manifest.py` and `attach_records.py`) writes a web-ready copy to `/workspace/gramps-web/web-ready/<folder>/<stem>.web.jpg|pdf`. Images become JPEG q85 at full size, then lower quality, then a downscale that keeps at least 2500 px on the long side. PDFs go through Ghostscript (`/usr/local/bin/gs`) at 300/200/150 dpi. The original is never changed. The Gramps media gets the attributes "Original file", "Original size (bytes)" and "Web-ready derivative". If no copy fits under 10 MiB, the entry goes to `shared/manifest_unmatched.csv` with "attach a page extract instead".
- **Audit overrides:** `shared/audit_mismatches.csv` lists files that were attached to the wrong person. `media_overrides.py` rewrites manifest entries on every run so those links are never re-created, and `apply_media_audit.py` keeps the fixes in force (unlink or relink, corrected titles, dates and URLs). The full audit is in `shared/media_audit_2026-11-18.csv`.
- **Record links:** `record_links.py` keeps exactly one note per person, starting "Record links", with one line per attached file that has a known URL (title, URL, record date). It is rebuilt from the current links on every run, so moved or unlinked files take their links with them.
